Project Overview

AI Desk Meter is a small desk device that shows usage percentage, reset countdowns, weekly usage, burn-rate warnings, and connection status for AI coding tools. The first target is Claude Code, but the architecture is intentionally service-agnostic.

Local-first

The computer reads usage data and sends a small payload to the device. The device does not need a cloud backend.

Hardware-simple

One ESP32-S3 AMOLED board, USB-C power, optional enclosure, optional BLE polish later.

Extensible

Provider model supports mock data, manual estimates, official APIs, logs, Codex, Gemini CLI, and local LLM tools.

Rule: this project displays usage information. It should not bypass limits, automate account rotation, scrape private dashboards, or violate service rules.

Hardware Target

Recommended board: Waveshare ESP32-S3-Touch-AMOLED-2.16 or similar 480×480 ESP32-S3 AMOLED display board. Use the exact vendor example for your board revision before wiring custom graphics.

Architecture

        ↓

        ↓
Normalize into JSON
        ↓
BLE or local Wi-Fi
        ↓
ESP32-S3 AMOLED firmware
        ↓
Usage bars + reset countdown + status animation
Desktop host

Reads usage, estimates reset windows, validates state, sends payloads, writes logs.

ESP32 firmware

Receives payloads, draws UI, shows stale/offline/error states, stays lightweight.

JSON Protocol

Send one compact JSON payload every 10–60 seconds. The display only needs the latest state.

{
  "schema": "ai-desk-meter.v1",
  "service": "claude-code",
  "current_percent": 50,
  "weekly_percent": 11,
  "current_reset_seconds": 4920,
  "weekly_reset_seconds": 547200,
  "burn_rate": "normal",
  "status": "Musing...",
  "mode": "active",
  "updated_at": 1760000000,
  "source": "local-provider",
  "confidence": "estimated"
}
FieldMeaning
current_percentCurrent usage window percentage, clamped 0–100.
weekly_percentWeekly or longer-period usage estimate.
burn_rateidle, low, normal, high, critical.
confidenceexact, estimated, mock, or unknown.

Manual provider

Fallback where exact usage data is unavailable.

Only when a legitimate usage source is available.

Local log provider

Reads local user-accessible logs where possible and marks confidence honestly.

MVP Build Plan

  1. Flash the vendor ESP32-S3 AMOLED display demo.
  2. Draw a static fake usage screen.
  3. Add Wi-Fi endpoint or WebSocket receiver.
  4. Send mock JSON from a Python host daemon.
  5. Add stale/offline/error handling.
  6. Add manual or real usage provider later.
  7. Build a simple enclosure only after the electronics work.

Testing Checklist

  • Bad JSON does not crash firmware.
  • Huge payload is rejected safely.
  • Host disconnect moves screen to stale/offline state.
  • Device can run for 8+ hours on USB power.
  • Percentages are clamped to 0–100.
  • Confidence label is visible when usage is estimated.
  • Mock payload updates are visible on real hardware.
